# Requirements: Fitness_App

**Defined:** 2026-06-01
**Core Value:** Users can accurately calculate their BMI and TDEE, log daily food intake by selecting ingredients and entering weight in grams, log physical activities with intensity-based calorie tracking, and understand their calorie balance — all in one integrated, easy-to-use English-language health tool.

## v1 Requirements

Requirements for v1.9 Progress Tracking milestone. Each maps to roadmap phases.

### Database & Schema

- [x] **DB-01**: weight_logs table created with columns (id, user_id, weight_kg, logged_date, source, notes, created_at) and UNIQUE(user_id, logged_date) constraint — ✅ Validated
- [x] **DB-02**: target_weight_kg and target_date columns added to profiles table — ✅ Validated
- [x] **DB-03**: Existing user weight backfilled — INSERT INTO weight_logs FROM profiles for every existing user on migration — ✅ Validated
- [x] **DB-04**: Index created on weight_logs(user_id, logged_date DESC) for efficient range queries — ✅ Validated

### Weight Logging

- [x] **WLOG-01**: Weight auto-logged to weight_logs when user updates profile via PUT /api/profile (non-blocking — profile update succeeds even if weight log fails) — ✅ Validated
- [x] **WLOG-02**: Weight auto-log is transactional — weight_log inserted AFTER profile update succeeds — ✅ Validated
- [x] **WLOG-03**: Second weight entry on same day UPSERTs (last-write-wins), not duplicates — ✅ Validated
- [x] **WLOG-04**: User can manually log weight via POST /api/progress/weight with weight, date, and optional notes — ✅ Validated
- [x] **WLOG-05**: User can view weight history list with date, weight, source badge, ordered by date DESC — ✅ Validated
- [x] **WLOG-06**: User can delete weight log entries — ✅ Validated
- [x] **WLOG-07**: Weight logged to history when profile is first created (seeds initial entry) — ✅ Validated

### Goal Setting

- [x] **GOAL-01**: User can set target weight (kg) and target date in profile form — ✅ Validated
- [x] **GOAL-02**: Goal fields included in PUT /api/profile and GET /api/profile responses — ✅ Validated
- [x] **GOAL-03**: Goal validation: target_weight 2-300kg, target_date >= today, direction matches fitness_goal — ✅ Validated

### Weight Chart

- [x] **CHRT-01**: Weight trend line chart rendered with Recharts on progress page — ✅ Validated
- [x] **CHRT-02**: X-axis shows dates, Y-axis shows weight with auto-scaled domain (dataMin - 2, dataMax + 2) — ✅ Validated
- [x] **CHRT-03**: Goal reference line (dashed horizontal line at target_weight_kg) displayed when goal is set — ✅ Validated
- [x] **CHRT-04**: Chart handles empty state (0 entries → prompt to log), insufficient data (1 entry → message), and normal display (2+ entries) — ✅ Validated
- [x] **CHRT-05**: Date range filter (30/60/90 days) to control chart time window — ✅ Validated

### Progress Dashboard

- [x] **DASH-01**: New /progress route with full dashboard page — ✅ Validated
- [x] **DASH-02**: Summary card showing current weight, starting weight, change, kg to goal, % complete — ⚠️ Not implemented (deferred)
- [x] **DASH-03**: Dashboard integrates chart, weight history table, manual weight entry form, and goal display — ✅ Validated
- [x] **DASH-04**: Loading, empty, and error states for all dashboard sub-components — ⚠️ Retry capability on error state deferred
- [x] **DASH-05**: Nav link to progress page added — ✅ Validated

### Trend Prediction (P2)

- [x] **TRND-01**: Estimated completion date calculated from actual weight trend (not calorie_rate) — ✅ Validated
- [x] **TRND-02**: Trend prediction displayed on dashboard when sufficient data exists (3+ entries, 2+ weeks) — ✅ Validated
- [x] **TRND-03**: Progress direction shown as rate (e.g., "losing 0.5 kg/week") with color coding — ✅ Validated

## Out of Scope

| Feature | Reason |
|---------|--------|
| Body fat / measurements tracking | Scope creep — weight-only for v1.9 |
| Smart scale / wearable integration | Requires external API, not core |
| Weight logging reminders / notifications | No push infrastructure exists |
| Multiple weight entries per day | One-entry-per-day (UPSERT pattern) — sufficient for daily weigh-in |
| Data export (CSV/PDF) | Nice-to-have, not core to progress tracking |
| Progress photos | Requires storage infrastructure |
| Separate goals table | Goal is 1:1 with profile — columns on profiles table is simpler |
