**Database schema (from Phase 42):**

`weight_logs` table:
```sql
CREATE TABLE IF NOT EXISTS weight_logs (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES profiles(user_id),
  weight_kg NUMERIC(5,1) NOT NULL,
  logged_date DATE NOT NULL,
  source VARCHAR(10) NOT NULL DEFAULT 'manual',  -- 'auto' or 'manual'
  notes TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, logged_date)
);
CREATE INDEX IF NOT EXISTS idx_weight_logs_user_date ON weight_logs(user_id, logged_date DESC);
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Spoofing | POST /api/progress/weight | mitigate | authenticateToken middleware at route level — req.user.userId from JWT |
| T-43-02 | Tampering | All weight/goal endpoints | mitigate | Server-side validation (weight 2-300kg, date >= today, direction check) via Zod-like validation in service layer |
| T-43-03 | Repudiation | weight_logs source field | mitigate | Source is set server-side ('auto' or 'manual') — never accepted from client input; prevents client from faking 'auto' entries |
| T-43-04 | Info Disclosure | GET /api/progress/weight | mitigate | Query scoped to req.user.userId — users cannot see each other's weight data |
| T-43-05 | Elevation of Privilege | DELETE /api/progress/weight/:id | mitigate | DELETE scoped by user_id — user can only delete their own entries |
| T-43-06 | Tampering | UPSERT weight entry | mitigate | ON CONFLICT upserts on UNIQUE(user_id, logged_date) — no duplicate injection possible |
</threat_model>
