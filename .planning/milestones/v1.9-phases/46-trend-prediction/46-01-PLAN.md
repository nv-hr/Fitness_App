  <action>
    Create two files: the hook module and its unit tests.

    **Hook file (useTrendPrediction.js)**

    Export TWO things: `linearRegressionOLS` (pure function) and `useTrendPrediction` (hook).

    `linearRegressionOLS(points)` — accepts `[{ x: number, y: number }]`:
    - Returns `null` if `n < 2`
    - Compute sums: sumX, sumY, sumXY, sumXX, sumYY
    - `denom = n * sumXX - sumX * sumX` — if denom === 0 return null
    - `slope = (n * sumXY - sumX * sumY) / denom`
    - `intercept = (sumY - slope * sumX) / n`
    - `r2 = (n * sumXY - sumX * sumY)^2 / ((n * sumXX - sumX * sumX) * (n * sumYY - sumY * sumY))` — if denomR2 <= 0, r2 = 0
    - Return `{ slope, intercept, r2 }`

    `useTrendPrediction(weightEntries, profile)` using `useMemo`:
    - Guard: if `weightEntries.length < 3`, return `{ insufficientData: true, noGoalSet: !profile?.target_weight_kg, direction: null, rateKgPerWeek: null, estimatedDate: null, confidence: null, kgToGoal: null, colorStatus: null, statusLabel: null }`
    - Sort entries ASC by `logged_date` localeCompare (use `[...entries].sort()`, DO NOT mutate original array per RESEARCH.md Pitfall 2)
    - Check span: if `differenceInDays(lastDate, firstDate) < 14`, return the same insufficientData shape
    - Build `points = sorted.map(e => ({ x: differenceInDays(parseISO(e.logged_date), firstDate), y: parseFloat(e.weight_kg) }))`
    - Call `linearRegressionOLS(points)` — if null, return insufficientData
    - `rateKgPerWeek = result.slope * 7`
    - Determine `direction`: `rateKgPerWeek < -0.01` → `'losing'`, `> 0.01` → `'gaining'`, else `'stable'`
    - Determine `colorStatus` and `statusLabel`:
      - If no `profile?.target_weight_kg` or no `profile?.target_date`: `colorStatus = 'neutral'`, `statusLabel = null`
      - Else compute `expectedRate = (targetWeight - currentWeight) / (daysUntilTarget / 7)` where daysUntilTarget = `differenceInDays(parseISO(profile.target_date), new Date())`
      - If `daysUntilTarget <= 0` → `colorStatus = 'neutral'`
      - Determine if rate direction is on-track per profile.fitness_goal:
        - `lose_weight`: on-track if `rateKgPerWeek < 0`
        - `build_muscle` or `gain_weight`: on-track if `rateKgPerWeek > 0`
        - `maintain`: on-track if `Math.abs(rateKgPerWeek) < 0.1`
      - For `maintain` goal: `Math.abs(rateKgPerWeek) < 0.1` → green + "On Track"; `< 0.25` → amber + "Slower than expected"; else → red + "Off Track"
      - For non-maintain: if not on-track → red + "Off Track". If on-track:
        - `ratio = Math.abs(rateKgPerWeek) / Math.abs(expectedRate)`
        - ratio >= 0.8 → green + "On Track"
        - ratio >= 0.4 → amber + "Slower than expected"
        - else → red + "Off Track"
    - Compute `kgToGoal`: `parseFloat(profile.target_weight_kg) - parseFloat(weightEntries[0].weight_kg)` (using most recent entry's weight as current)
    - Compute `estimatedDate`:
      - Only if `colorStatus !== 'neutral' && colorStatus !== null && rateKgPerWeek !== 0`
      - `daysToGoal = Math.abs(kgToGoal / rateKgPerWeek) * 7`
      - If `kgToGoal` and `rateKgPerWeek` have opposite signs (moving away from goal) → null
      - Else `addDays(new Date(), Math.round(daysToGoal))`
    - Compute `confidence`: `result.r2` rounded to 2 decimal places
    - Compute `statusLabel` based on confidence text: `>= 0.7` → `"(strong fit)"`, `>= 0.4` → `"(moderate fit)"`, else `"(weak fit)"`
    - Include `noGoalSet: !profile?.target_weight_kg || !profile?.target_date` in the final return object (not just the guard path)
    - Return full result object.

    Edge cases to handle per RESEARCH.md pitfalls:
    - Division by zero: guard `denom === 0` in OLS
    - NaN from missing profile: guard all profile field access with `?.` and truthiness checks
    - ASC/DESC order: always sort explicitly, never rely on API order
    - Date string vs Date object: always use `parseISO()` for ISO strings, `new Date()` for today
    - Opposite direction edge case: direction verb from data, colorStatus from goal-direction match + rate threshold
