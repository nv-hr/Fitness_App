# Milestone v1.6: Activity Planner Rework

**Status:** ✅ SHIPPED 2026-05-31
**Phases:** 30-33
**Total Plans:** 8
**Commits:** 62

## Overview

Overhaul activity planning to support variable-day weekly schedules with rest days, LLM-driven activity selection based on user profile, and per-activity swapping.

## Phases

### Phase 30: Prompt & Validation Rework

**Goal**: LLM generates variable-day plans with profile-driven activity selection and rest days
**Depends on**: Phase 29
**Plans**: 2 plans

Plans:

- [x] 30-01: Core prompts & service (weekly-plan-prompt.md, llm.service.js validation/generation) — completed 2026-05-31
- [x] 30-02: Controller wiring & tests (availableDays passthrough, test coverage) — completed 2026-05-31

**Details:**
- Generated plans respect the availableDays parameter — exactly N activity days (4-6) with remaining days as rest
- Plan activities reflect the user's fitness goal (lose weight / maintain / build muscle)
- Activity duration and intensity scale with user's activity level
- Multiple activities per day are assigned when user profile supports it
- All plan_data includes format_version field distinguishing old vs new format

### Phase 31: Activity Swap Endpoint

**Goal**: Users can swap a single activity via dedicated backend endpoint with rate limiting
**Depends on**: Phase 30
**Plans**: 2 plans

Plans:

- [x] 31-01: Core service & prompt (activity-swap-prompt.md, swapActivity(), swapLimiter) — completed 2026-05-31
- [x] 31-02: Controller, route, DB persistence & tests (swapHandler, POST /swap, upsertPlan, E2E) — completed 2026-05-31

**Details:**
- User can request a swap for a specific activity via API and receive a replacement
- LLM returns a contextually appropriate replacement activity
- Swapped activity merges into the cached plan in-place without full regeneration
- Swap requests are rate-limited independently from generate/regenerate

### Phase 32: Frontend — Days Selector & Swap UI

**Goal**: Users can configure available days before generating and swap activities from the plan view
**Depends on**: Phase 31
**Plans**: 2 plans

Plans:

- [x] 32-01: Toast component & API layer (swapActivity, availableDays in generateWeeklyPlan) — completed 2026-05-31
- [x] 32-02: Days selector panel, rest day cards, swap button, WeeklyPlanPage wiring — completed 2026-05-31

**Details:**
- User can select 4-6 available days from a visual selector in the plan generation form
- Rest days display as dedicated rest day cards in the weekly plan view
- Each activity has a visible Swap button
- Swap initiates a mutation with loading state and updates the activity in-place on success

### Phase 33: Plan Migration & Edge Cases

**Goal**: Existing old-format plans migrate seamlessly; edge cases handled gracefully
**Depends on**: Phase 32
**Plans**: 2 plans

Plans:

- [x] 33-01: Lazy migration (GET + swapHandler) + 404 fix for nonexistent activityId — completed 2026-05-31
- [x] 33-02: Unit + E2E tests for migration flows and swap edge cases — completed 2026-05-31

**Details:**
- Old-format 7-day plans automatically regenerate with variable-day format on user's next visit
- Migration is transparent — no data loss, no visible errors
- Swap edge cases (nonexistent activity ID, already-swapped activity) display appropriate error messages

## Milestone Summary

### Key Decisions

| Decision | Rationale | Where Implemented |
|----------|-----------|-------------------|
| rest_day boolean flag on each day (7-day template) | Fixed template avoids variable-length output issues | Phase 30 — weekly-plan-prompt.md + validatePlanStructure |
| format_version: 1 at plan root | Migration detection for old-format plans | Phase 30 — generateWeeklyPlan structure |
| Goal-specific prompt sections | Profile-driven activity selection (lose weight/maintain/build muscle) | Phase 30 — prompt includes conditional sections |
| Self-contained swap prompt | No dependency on weekly-plan-prompt, single-activity focus | Phase 31 — activity-swap-prompt.md |
| DB-first write + per-user async mutex | Prevents dual-write inconsistency and TOCTOU race | Phase 31 — swapActivity + swapHandler |
| expandable days selector panel (7 checkboxes) | Simple UI for availableDays configuration | Phase 32 — EmptyStatePlan.jsx |
| Green rest day cards (#f0fdf4) | Clear visual distinction for rest days | Phase 32 — DayCard.jsx |
| 5-minute migration cooldown | Prevents infinite LLM retry on failure | Phase 33 — migrationFailCooldown Map |
| Lazy migration on GET request | Transparent migration — no user notification | Phase 33 — controller GET handler |
| Swap triggers auto-migration on old-format plans | Prevents 404 on nonexistent activities in old format | Phase 33 — swapHandler |

### Issues Resolved

- Per-user async mutex for concurrent swapActivity/regenerateDay operations
- Swap merge updates both cache (node-cache) and DB (weekly_plans table)
- Error code mismatch: frontend now checks `NOT_FOUND_ERROR` matching backend error middleware
- Migration cooldown now set in both GET and swapHandler paths

### Issues Deferred

None.

### Technical Debt Incurred
