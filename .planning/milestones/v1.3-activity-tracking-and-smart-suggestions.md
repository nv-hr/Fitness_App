# Milestone v1.3: Activity Tracking & Smart Suggestions

**Status:** ✅ SHIPPED 2026-05-31
**Phases:** 13-17
**Total Plans:** 9

## Overview

Users can log physical activities with duration/intensity, view daily calorie balance including exercise, and receive personalized LLM-generated weekly activity plans.

### Phase 14: Activity Logger

**Goal**: Users can log activities, view history, delete entries, and see daily net calorie summary including exercise
**Depends on**: Phase 13
**Plans**: 1 plan (12 tasks)

Plans:

- [x] 14-01: Activity logger full feature — backend API + frontend UI

**Details:**
- POST /api/activities/log — log activity with activityId, durationMin, intensity, loggedDate

### Phase 15: LLM Backend Integration

**Goal**: System can generate personalized weekly activity plans via OpenRouter with caching, rate limiting, API key management, and graceful fallback
**Depends on**: Phase 14
**Plans**: 3 plans

Plans:

- [x] 15-01: LLM Service Foundation — prompt templates, OpenRouter client, core API call
- [x] 15-02: Output Validation, Caching & Fallback — structural validation, fuzzy matching, retry logic, fallback plan
- [x] 15-03: Rate Limiting & API Endpoint — per-user rate limiter, controller, route registration

**Details:**
- OpenRouter integration via OpenAI SDK with configurable model and API key from env
- buildPrompt/buildSystemPrompt with profile and activity history context
- validatePlanStructure + fuzzyMatchActivityName + validateAndFixPlan pipeline
- In-memory cache (node-cache) + DB persistence (weekly_plans table) with TTL
- generateFallbackPlan using recent activity history
- Rate-limited endpoints (5 req/15 min per user) with retry-after headers
- POST /api/weekly-plans/generate and POST /api/weekly-plans/regenerate-day

## Milestone Summary

**Key Decisions:**
- Intensity multipliers: light=0.7, moderate=1.0, vigorous=1.3 (server authoritative)
- LLM rate-limited to 5 req/15 min for cost control
- GET endpoint returns cached plan with fromCache flag (no DB hit, no rate-limit consumption)
- regenerateDay generates full plan but merges only one day into existing cached plan
- Per-day retryAfter tracked in dayRetryAfters object keyed by dayIndex
- getMonday helper computes ISO week start; week start computed client-side
- Activity Logger is independent and shipped first (Phases 13-14)
- LLM feature depends on activity history (Phase 14 complete before Phase 15)
- DB changes: new activity_logs table, weekly_plans (JSONB), intensity_level ENUM
- 2 new npm packages: openai@^6.1.0, node-cache@^5.1.2

**Issues Resolved:**
- Integration test fixes for checkDbConnection and describeIf graceful skip
- Session pooler retest — all 81 backend tests pass
- Frontend itWhenReady fix + activityLevel mismatch
- Code review fixes: ProfileGuard on /weekly-plan route, null guard for plan_data, $ pattern injection fix, activity name overwrite fix, timezone normalization (UTC vs local)

**Issues Deferred:**
- LLM cost monitoring not yet implemented
- LLM prompt templates may need refinement for production quality

**Technical Debt Incurred:**
- No separate monitoring for LLM token usage
- Some inline styles in weekly-plan components (no CSS module migration)
