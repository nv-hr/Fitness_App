# Plan: Fix Google OAuth Callback 500

## Objective

Fix `GET /api/auth/google/callback` returning HTTP 500 by adding error handling
that redirects to the frontend login page with an error message instead of
crashing to a raw JSON error response.

## Symptoms

```
GET /api/auth/google 302 0.602 ms - 0
GET /api/auth/google/callback?iss=... 500 234.960 ms - 93
```

The Google redirect works (302), but the callback handler crashes (500).

## Root Cause

1. **Missing error handling in callback route** — When Passport's
   `authenticate('google', ...)` middleware encounters an error (DB unreachable,
   token exchange failure, etc.), it calls `next(err)` → Express global error
   handler → raw 500 JSON response. The user never gets redirected to the
   frontend.

2. **`GOOGLE_CALLBACK_URL` missing from `.env`** — Present in `.env.example`
   but not in the active `.env`. While the code has a default fallback
   `http://localhost:3001/...`, having the explicit config prevents drift
   between the registered redirect URI and the runtime value.

## Tasks

### Task 1: Add `GOOGLE_CALLBACK_URL` to `.env`

**Files:** `backend/.env`

**Action:** Add `GOOGLE_CALLBACK_URL=http://localhost:3001/api/auth/google/callback`
to `backend/.env`, matching the value in `.env.example`. Insert it after the
`GOOGLE_CLIENT_SECRET` line.

**Why:** Makes the callback URL explicit in configuration. The code defaults to
this value, but having it in `.env` prevents subtle drift issues.


**Done:** `backend/.env` contains `GOOGLE_CALLBACK_URL=http://localhost:3001/api/auth/google/callback`

### Task 2: Wrap Google callback route with error-handling redirect

**Files:** `backend/src/app.js` (lines 145-152)

**Action:** Replace the current Google OAuth callback route definition to
catch errors from Passport and redirect to the frontend login page instead of
calling `next(err)`.

**Current code (lines 145-152):**
```javascript
app.get(
  '/api/auth/google/callback',
  passport.authenticate('google', {
    session: false,
    failureRedirect: FRONTEND_URL + '/login',
  }),
  authController.googleCallback
);
```

**Replace with:**
```javascript
app.get(
  '/api/auth/google/callback',
  (req, res, next) => {
    const cb = passport.authenticate('google', {
      session: false,
      failureRedirect: FRONTEND_URL + '/login?error=google_auth_failed',
    });
    cb(req, res, (err) => {
      if (err) {
        console.error('Google OAuth callback error:', err.message);
        return res.redirect(`${FRONTEND_URL}/login?error=google_auth_error`);
      }
      next();
    });
  },
  authController.googleCallback
);
```

**What this does:**
- The `passport.authenticate()` returned middleware normally calls `next(err)`
  on error → Express error handler → raw 500 JSON
- By passing a custom callback to the middleware, we intercept the error
  before it reaches Express's error handler
- On error: redirect to `FRONTEND_URL/login?error=google_auth_error`
- On Passport `failureRedirect` (user denies consent): redirect to
  `FRONTEND_URL/login?error=google_auth_failed`
- On success: proceed to `authController.googleCallback` as before

**Verify:**
```bash

  const content = fs.readFileSync('backend/src/app.js', 'utf8');
  // Confirm the callback route has error handling
  const cbMatch = content.match(/google.*callback[\s\S]{0,500}authController\.googleCallback/);
  if (cbMatch && cbMatch[0].includes('error=google_auth_error')) {
    console.log('OK: Error handling redirect present');
  } else {
    console.log('FAIL: Error handling redirect missing');

  }
"
```

**Done:** Google OAuth callback errors redirect to frontend login with error
parameter instead of returning raw 500 JSON.
