# Quick Task 260601-m13: Fix Activity Calendar persistence

## What was done

Added best-effort sync from the `logActivity` endpoint to the weekly plan's activity `completed` state in `activity.controller.js`. After creating an activity log entry, the controller now:

1. Calculates the week start from the log date
2. Finds the weekly plan for that user and week
3. Locates the day matching the log date
4. Finds the activity by `activityId` in that day
5. Sets `completed = true` on the activity
6. Recomputes the day-level `completed` flag
7. Persists via `upsertPlan`
8. Updates the server cache via `setCachedPlan`

This mirrors the same pattern used in the food fix (260601-237) where `createFoodLog` syncs to `markItemLogged` in the daily meal plan.

## Verification

- Backend unit tests: 6/7 suites pass (1 pre-existing failure in llm.service.test.js unrelated to this change)
- The frontend `ActivityCalendarSection` already reads `act.completed` from the plan on every fetch and populates `completedActivities` accordingly, so no frontend change was needed.
