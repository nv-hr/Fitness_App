<objective>
Fix `NaN/NaN` displayed in the calorie history date column after inserting a new food log entry.

**Root cause (two-sided):**
1. **Backend:** PostgreSQL `DATE` column `log_date` is parsed by `postgres-date` into a JS `Date` object. When Express serializes the response via `JSON.stringify`, it produces `"2025-05-28T00:00:00.000Z"` (full ISO 8601) instead of `"2025-05-28"`.
2. **Frontend:** `formatDate()` does `new Date(dateStr + 'T00:00:00')` assuming `dateStr` is `YYYY-MM-DD`. Receiving `"2025-05-28T00:00:00.000Z"` produces `"2025-05-28T00:00:00.000ZT00:00:00"` → Invalid Date → `getDate()` returns NaN.

**Fix:** Backend normalizes `log_date` to `YYYY-MM-DD` string in `getLogHistory`. Frontend tolerates both date formats in `formatDate`.
</objective>
