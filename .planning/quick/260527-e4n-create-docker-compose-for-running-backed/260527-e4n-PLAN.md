## Objective

Add `backend/Dockerfile` and `frontend/Dockerfile`, then wire both into `docker-compose.yml` alongside the existing MySQL + Adminer services.

**Purpose:** One-command startup for the full stack via `docker compose up`.
**Output:** Working `docker compose up` that starts MySQL → backend → frontend.

## Context

- `docker-compose.yml` already has MySQL 8.4 + Adminer on a `fitness_net` bridge network.
- Backend (Express, port 3001) reads `DB_HOST` from env — defaults to `localhost` if unset.
- Frontend (Vite, port 5173) proxies `/api` to `http://localhost:3001` — hardcoded in `vite.config.js`.
- Backend `.dockerignore` exists; no frontend `.dockerignore`.
- No Dockerfiles exist yet.

## Tasks

### Task 1: Create `backend/Dockerfile`

**Files:** `backend/Dockerfile`

**Action:** Create a Node.js 20 Alpine Dockerfile for the Express API server.

Requirements:
- Base image: `node:20-alpine`
- Working directory: `/app`
- Copy `package*.json` first, run `npm install` (layer caching)
- Copy rest of source code
- `EXPOSE 3001`
- Default CMD: `npm run dev` (nodemon with hot-reload in dev)
- No `.env` copied — secrets come via docker-compose `env_file` or `environment`

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production || npm install
COPY . .
EXPOSE 3001
CMD ["npm", "run", "dev"]
```

**Verify:**
```bash
docker build -t fitness-backend -f backend/Dockerfile backend
```
Runs without error.

**Done:** `backend/Dockerfile` exists, builds successfully.

### Task 2: Create `frontend/Dockerfile` + update Vite proxy config

**Files:** `frontend/Dockerfile`, `frontend/vite.config.js`

**Action 2a:** Create `frontend/Dockerfile` for the Vite dev server.

- Same base pattern as backend (Node 20 Alpine)
- `EXPOSE 5173`
- `CMD ["npm", "run", "dev"]`
- No `.dockerignore` exists for frontend — create one that excludes `node_modules`, `dist`, `.env` (even if not present)

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production || npm install
COPY . .
EXPOSE 5173
CMD ["npm", "run", "dev"]
```

**Action 2b:** Update `vite.config.js` to make the proxy target configurable via env var `VITE_API_PROXY_TARGET`, defaulting to `http://localhost:3001` (backward compatible with local dev).

Current code:
```js
target: 'http://localhost:3001',
```

Change to:
```js
target: process.env.VITE_API_PROXY_TARGET || 'http://localhost:3001',
```

This allows docker-compose to set `VITE_API_PROXY_TARGET=http://backend:3001` so the Vite dev server inside Docker proxies to the backend service by container name.

**Action 2c:** Create `frontend/.dockerignore`:

```
node_modules
dist
.env
.dockerignore
```

**Verify:**
- `docker build -t fitness-frontend -f frontend/Dockerfile frontend` succeeds
- Check that `vite.config.js` contains `process.env.VITE_API_PROXY_TARGET`

**Done:** Both Dockerfiles build. Proxy target is env-configurable.

### Task 3: Wire frontend + backend into `docker-compose.yml`

**Files:** `docker-compose.yml`

**Action:** Add `backend` and `frontend` services to the existing `docker-compose.yml`. Keep MySQL and Adminer unchanged.

**Backend service:**
- `build: ./backend`
- `container_name: fitness_backend`
- Depends on `mysql` (condition: `service_healthy`)
- Port `3001:3001`
- Env vars (passed via `environment` block):
  - `DB_HOST=mysql` (service name — overrides `localhost` default)
  - `DB_PORT=3306`
  - `DB_USER`, `DB_PASSWORD`, `DB_ROOT_PASSWORD`, `DB_NAME=fitness_app` — mirror values from `.env` but source from `${DB_USER}` etc. via env interpolation
  - `JWT_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- `env_file: ./backend/.env` (single source of truth for secrets)
- Network: `fitness_net`
- `restart: unless-stopped`

**Frontend service:**
- `build: ./frontend`
- `container_name: fitness_frontend`
- Depends on `backend` (simple `depends_on`, no healthcheck needed)
- Port `5173:5173`
- `environment`:
  - `VITE_API_PROXY_TARGET=http://backend:3001`
- Network: `fitness_net`
- `restart: unless-stopped`

**Updated compose file outline:**

```yaml
services:
  mysql:
    # ... unchanged from existing ...

  adminer:
    # ... unchanged from existing ...

  backend:
    build: ./backend
    container_name: fitness_backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "3001:3001"
    env_file:
      - ./backend/.env
    environment:
      - DB_HOST=mysql
      - DB_PORT=3306
      - DB_NAME=fitness_app
    networks:
      - fitness_net

  frontend:
    build: ./frontend
    container_name: fitness_frontend
    restart: unless-stopped
    depends_on:
      - backend
    ports:
      - "5173:5173"
    environment:
      - VITE_API_PROXY_TARGET=http://backend:3001
    networks:
      - fitness_net

volumes:
  mysql_data:

networks:
  fitness_net:
    driver: bridge
```

**Important details:**
- Use `env_file: ./backend/.env` for the backend so all 5 secrets (DB_ROOT_PASSWORD, DB_USER, DB_PASSWORD, JWT_SECRET, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET) come from the single `.env` file without duplication.
- The `environment` block sets only the Docker-specific overrides (`DB_HOST`, `DB_PORT`, `DB_NAME`) — these take precedence over `env_file` values per Docker's merge rules.
- Frontend does NOT need `env_file` — only the `VITE_API_PROXY_TARGET` env var.

**Verify:**
```bash
docker compose config
```
Validates without error (checks YAML and service definitions).

Then optionally test:
```bash
docker compose up -d
docker compose ps
# Check all 4 containers are running
```

**Done:** `docker-compose.yml` has all 4 services, `docker compose config` validates clean.
