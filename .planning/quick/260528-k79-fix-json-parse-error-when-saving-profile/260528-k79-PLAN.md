<objective>
Fix `SyntaxError: Unexpected token 'T', "Too many profile requests" is not valid JSON` that occurs when the `express-rate-limit` sends `text/plain` and the frontend calls `response.json()` unconditionally.

**Root cause (two-sided):**
1. **Backend:** `createRateLimiter()` passes plain string `message` to `express-rate-limit`, which sends it as `text/plain` with HTTP 429. The frontend expects JSON everywhere.
2. **Frontend:** `apiFetch()` calls `response.json()` unconditionally — no content-type check before parsing.

**Fix:** Backend sends JSON error envelopes from all rate limiters (matching the existing `errorResponse` format). Frontend defensively checks content-type before calling `.json()`.
</objective>

    } else {
      // Non-JSON response (e.g., rate limiter text/plain, server error HTML)
      const text = await response.text();
      if (!response.ok) {
        throw new Error(text || 'Request failed');
