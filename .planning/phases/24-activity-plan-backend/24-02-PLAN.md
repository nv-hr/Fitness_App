<objective>
Create the service, controller, and route layers for the activity plans persistence feature.

Purpose: Wire up the persistence logic so that when an activity plan is generated, it's saved to the `activity_plans` table. Users can then retrieve their plan for any date via a GET endpoint that prefers fast node-cache first, then falls back to the database. Each activity item in plan_data gets `logged: false` by default, with `markActivitiesLogged()` available for Phase 25's batch-log feature.

- `backend/src/controllers/activityPlan.controller.js` — GET and generate handlers

- `backend/src/app.js` — Route registration
</objective>

    **export async function generateActivityPlan(deps)**

    Purpose: Generate a 7-day activity plan (reuse existing LLM logic) and persist each day's activities to the `activity_plans` table.

    `deps` shape: `{ getProfile, getActivityHistory, getActivities, getTopActivities, userId, weekStart }`
    — identical to what `generateWeeklyPlan` expects.

    Implementation steps:
    1. Call `const result = await generateWeeklyPlan(deps);`
       - result = `{ plan: { days: [...], status, generated_at, ... }, fromCache: boolean, status: string }`
    2. If `result.plan` has no `days` array (null, missing, empty), return result as-is (nothing to persist)
    3. Get `plan = result.plan`
    4. For each `day` in `plan.days`:
       a. Build `planData` object:
          ```javascript
          const planData = {
            activities: day.activities.map(a => ({
              activity_id: a.activity_id,
              name: a.name,
              duration_min: a.duration_min,
              intensity: a.intensity,
              logged: false,  // Default — per ACT-03
            })),
            status: plan.status,
            generated_at: plan.generated_at || new Date().toISOString(),
          };
          ```
       b. Call `await upsertPlan(deps.userId, day.date, planData, plan.status);`
       c. Wrap each upsertPlan call in try/catch that logs a warning but does NOT throw (partial persistence is better than losing the whole plan)
    5. Return the original `result` (the caller already has the plan from the LLM return value — persistence is a side effect)

    **Important design decisions (per D-02/D-03):**
    - The cache is set by `generateWeeklyPlan()` before returning — the persistence here is additive, not cached
    - Each day is stored as a separate row keyed by (user_id, plan_date)
    - `ON CONFLICT` in upsertPlan means re-generation overwrites the existing row
    - `logged: false` is set fresh on every activity item on every persist — never preserved from a previous upsert (logged state is managed separately via markActivitiesLogged)
    - If a day has no activities, skip it (no empty row)
    - Do NOT call `markActivitiesLogged` here — that's for Phase 25's batch-log endpoint

    Use console.warn for logging persistence issues, e.g.:
    ```javascript
    console.warn(`[ActivityPlan] Failed to persist day ${day.date}: ${err.message}`);
    ```

    **function isValidDateString(str)** — copy from existing controllers:
    ```javascript
    function isValidDateString(str) {
      if (typeof str !== 'string') return false;
      const d = new Date(str + 'T00:00:00Z');
      return !isNaN(d.getTime());
    }
    ```

    **async function get(req, res, next)**

    Purpose: Return the activity plan for a given date. Cache-first: check node-cache for the week plan, then fall back to DB.

    Implementation:
    1. `const userId = req.user.userId;`
    2. `let planDate = req.query.date;`
    3. Validate if provided: `if (planDate && !isValidDateString(planDate)) return errorResponse(res, 'Invalid date format', 400, 'VALIDATION_ERROR');`
    4. Default: `planDate = planDate || new Date().toISOString().split('T')[0];`
    5. Compute `weekStart` from `planDate`: `const weekStart = getMonday(new Date(planDate));`
    6. **Cache check:** `const cached = getCachedPlan(userId, weekStart);`
       - If cached and `cached.status !== 'fallback'`:
         - Find the day in `cached.days` where `day.date === planDate`
         - If found, extract and return:
           ```javascript
           const plan = {
             activities: day.activities.map(a => ({
               activity_id: a.activity_id,
               name: a.name,
               duration_min: a.duration_min,
               intensity: a.intensity,
               logged: a.logged !== undefined ? a.logged : false,
             })),
             status: cached.status,
             generated_at: cached.generated_at,
           };
           return successResponse(res, { plan, fromCache: true });
           ```
         - If day not found in cached plan (shouldn't happen, but handle): fall through to DB
    7. **DB fallback:** `const dbPlan = await findByUserAndDate(userId, planDate);`
    8. If not found: `return successResponse(res, { plan: null, fromCache: false });`
    9. If found: `return successResponse(res, { plan: dbPlan.plan_data, fromCache: false });`
       - `dbPlan.plan_data` already contains `{ activities, status, generated_at }` with logged flags

    **async function generate(req, res, next)**

    Purpose: Generate a new activity plan and persist to DB.

    Implementation:
    1. `const userId = req.user.userId;`
    2. Compute weekStart from optional body param or default:
       ```javascript
       let weekStart = req.body.weekStart;
       if (weekStart && !isValidDateString(weekStart)) return errorResponse(res, 'Invalid weekStart date format', 400, 'VALIDATION_ERROR');
       weekStart = getMonday(weekStart ? new Date(weekStart) : new Date());
       ```
    3. Call `const result = await generateActivityPlan({ ... });`
       - The DI object needs the same deps as generateWeeklyPlan:
         ```javascript
         const result = await generateActivityPlan({
           getProfile: (id) => import('../repositories/profile.repository.js').then(m => m.findByUserId(id)),
           getActivityHistory: (id, days) => import('../repositories/activity.repository.js').then(m => m.getActivityHistoryWithEntries(id, days)),
           getActivities: () => import('../repositories/activity.repository.js').then(m => m.getAllActivities()),
           getTopActivities: (id, limit) => import('../repositories/activity.repository.js').then(m => m.getTopActivities(id, limit)),
           userId,
           weekStart,
         });
         ```
       - Use dynamic imports inside the handler to avoid top-level import errors (following existing pattern in weeklyPlan.controller.js)
       - Actually, looking at the existing pattern more carefully:
         - weeklyPlan.controller.js imports at the top: `import { findByUserId as findProfileByUserId } from '../repositories/profile.repository.js';`
         - mealPlan.controller.js also imports at the top
         
         So use top-level static imports:
         ```javascript
         import { findByUserId } from '../repositories/profile.repository.js';
         import { getActivityHistoryWithEntries, getAllActivities, getTopActivities } from '../repositories/activity.repository.js';
         ```
    4. Return `return successResponse(res, result);`

    Export default:
    ```javascript
    export default { get, generate };
    ```
    
    Note: `generate` method should NOT have rate limiting applied here — Phase 28 will handle that globally. Keep the handler simple.
