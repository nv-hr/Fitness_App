    Create `backend/src/repositories/activityPlan.repository.js` following the `mealPlan.repository.js` pattern but adapted for per-day activity plans.

    Imports:
    - `import { pool } from '../config/database.js';`
    - `import { AppError } from '../utils/errors.js';`

    **export async function findByUserAndDate(userId, planDate, clientOverride)**
    - Default `clientOverride || pool`
    - SQL: `SELECT id, user_id, plan_date, plan_data, status, created_at, updated_at FROM activity_plans WHERE user_id = $1 AND plan_date = $2 LIMIT 1`
    - Wrap in try/catch with AppError('DatabaseError', `Failed to find activity plan: ${err.message}`, 500)
    - Return `rows[0] || null`

    **export async function upsertPlan(userId, planDate, planData, status = 'active', clientOverride)**
    - Default `clientOverride || pool`
    - SQL: `INSERT INTO activity_plans (user_id, plan_date, plan_data, status) VALUES ($1, $2, $3::jsonb, $4) ON CONFLICT (user_id, plan_date) DO UPDATE SET plan_data = $3::jsonb, status = $4, updated_at = NOW() RETURNING id, user_id, plan_date, plan_data, status, created_at, updated_at`
    - Parameters: `[userId, planDate, JSON.stringify(planData), status]`
    - Wrap in try/catch with AppError('DatabaseError', `Failed to upsert activity plan: ${err.message}`, 500)
    - Return `rows[0] || null`

    **export async function markActivitiesLogged(userId, planDate, activityIndexes, clientOverride)**
    - Supports `clientOverride` parameter for transaction use (Phase 25)
    - Call `findByUserAndDate(userId, planDate, clientOverride)` to get the plan row
    - If no plan, return null
    - Extract `data = plan.plan_data`
    - Validate `data.activities` is an array; if not present or not array, return null
    - For each index in `activityIndexes`: if `data.activities[idx]` exists, set `data.activities[idx].logged = true`
    - Call `return upsertPlan(userId, planDate, data, plan.status, clientOverride)` to persist
    - Wrap in try/catch with AppError('DatabaseError', `Failed to mark activities logged: ${err.message}`, 500)

    Export default object with all three functions:
    ```
    export default { findByUserAndDate, upsertPlan, markActivitiesLogged };
    ```
    
    DO use named exports (for flexibility) AND a default export (for convenient imports) — same pattern as mealPlan.repository.js uses named exports only. Actually follow the mealPlan pattern: only named exports, no default export.
