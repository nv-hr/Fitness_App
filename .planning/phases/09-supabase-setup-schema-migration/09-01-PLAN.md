  <action>
    Create `backend/db/schema.sql` — idempotent PostgreSQL DDL translating the MySQL schema from `backend/db/init.sql`. 

    Apply these locked decisions from CONTEXT.md:
    - D-08: PostgreSQL ENUMs (CREATE TYPE ... AS ENUM) for: gender ('male','female','other'), fitness_goal ('lose_weight','maintain','gain_weight'), activity_level ('low','medium','high'), food_category ('proteins','carbs','vegetables','fruits','dairy','fats','drinks','other'), meal_type ('breakfast','lunch','dinner','snack'). Create all types BEFORE any table references.
    - D-09: Use GENERATED BY DEFAULT AS IDENTITY for all auto-increment PKs (NOT SERIAL).
    - D-10: Use TIMESTAMPTZ for all timestamp columns with DEFAULT NOW() for created_at.
    - D-11: Application-managed updated_at — set column type to TIMESTAMPTZ DEFAULT NOW() but do NOT add any PostgreSQL trigger. Application sets updated_at from Node.js code on updates.
    - D-12: Use JSONB for goal_tags and equipment_needed columns with DEFAULT '[]'::jsonb.
    - D-16: Separate file — schema.sql contains DDL only (no seed data).

    Table definitions (translate each from init.sql):
    1. **users**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), email (VARCHAR(255) UNIQUE), password_hash (VARCHAR(255) NULL), google_id (VARCHAR(255) UNIQUE NULL), pdp_consent (BOOLEAN DEFAULT FALSE — MySQL TINYINT(1)→PostgreSQL BOOLEAN), pdp_consent_date (TIMESTAMPTZ NULL), created_at (TIMESTAMPTZ DEFAULT NOW()), updated_at (TIMESTAMPTZ DEFAULT NOW())
    2. **profiles**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), user_id (INT NOT NULL UNIQUE), weight_kg (DECIMAL(5,2) NOT NULL), height_cm (DECIMAL(5,2) NOT NULL), age (INT NOT NULL), gender (gender NOT NULL — references ENUM), fitness_goal (fitness_goal NOT NULL), activity_level (activity_level NULL), created_at (TIMESTAMPTZ DEFAULT NOW()), updated_at (TIMESTAMPTZ DEFAULT NOW()), FOREIGN KEY user_id→users(id) ON DELETE CASCADE
    3. **foods**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), user_id (INT NULL), name (VARCHAR(255) NOT NULL), calories_per_100g (INT NOT NULL), category (food_category NOT NULL — references ENUM), is_custom (BOOLEAN DEFAULT FALSE), created_at (TIMESTAMPTZ DEFAULT NOW()), INDEXES: idx_name (name), idx_user_category (user_id, category), FOREIGN KEY user_id→users(id) ON DELETE CASCADE
    4. **food_logs**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), user_id (INT NOT NULL), food_id (INT NULL), custom_food_name (VARCHAR(255) NULL), calories (INT NOT NULL), portion_grams (INT NOT NULL), log_date (DATE NOT NULL), meal_type (meal_type NOT NULL — references ENUM), created_at (TIMESTAMPTZ DEFAULT NOW()), INDEXES: idx_user_date (user_id, log_date), idx_user_recent (user_id, log_date DESC), FOREIGN KEY user_id→users(id) ON DELETE CASCADE, FOREIGN KEY food_id→foods(id) ON DELETE SET NULL
    5. **activities**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), name (VARCHAR(255) NOT NULL), description (TEXT NOT NULL), duration_min (INT NOT NULL), estimated_calories (INT NOT NULL), goal_tags (JSONB NOT NULL DEFAULT '[]'::jsonb), equipment_needed (JSONB NOT NULL DEFAULT '[]'::jsonb), created_at (TIMESTAMPTZ DEFAULT NOW())
    6. **user_activity_log**: id (INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY), user_id (INT NOT NULL), activity_id (INT NOT NULL), completed_date (DATE NOT NULL), notes (TEXT NULL), created_at (TIMESTAMPTZ DEFAULT NOW()), INDEX: idx_user_date (user_id, completed_date), FOREIGN KEY user_id→users(id) ON DELETE CASCADE, FOREIGN KEY activity_id→activities(id) ON DELETE CASCADE

    Idempotency rules:
    - Use CREATE TYPE IF NOT EXISTS for all ENUMs
    - Use CREATE TABLE IF NOT EXISTS for all tables
    - Create indexes with IF NOT EXISTS: CREATE INDEX IF NOT EXISTS idx_name ON foods(name)

    Ordering: CREATE TYPES → CREATE TABLES (users → profiles → foods → food_logs → activities → user_activity_log) → CREATE INDEXES.

    Do NOT include:
    - CREATE DATABASE (Supabase provides the database)
    - USE fitness_app (PostgreSQL doesn't use this)
    - ENGINE=InnoDB (MySQL-specific)
    - COMMENT syntax from MySQL
    - Any MySQL-only features
  </action>

    1. TRUNCATE activities CASCADE; TRUNCATE foods CASCADE; (re-runnable safety — clears existing data before seed)
    2. Reset sequences: ALTER SEQUENCE activities_id_seq RESTART; ALTER SEQUENCE foods_id_seq RESTART;
    3. 35 activity INSERTs (translated from init.sql lines 127-172)
    4. 201+ food ingredient INSERTs across all 8 categories (translated from init.sql lines 181-403)

    Translation rules for INSERT statements:

    **Activities (35 rows from init.sql lines 127-172):**
    - Keep existing English names and Indonesian descriptions as-is (Phase 05 content, not affected by Phase 08 English migration)
    - goal_tags: MySQL `'["lose_weight", "maintain"]'` → PostgreSQL `'["lose_weight", "maintain"]'::jsonb`
    - equipment_needed: MySQL `'[]'` or `'["kursi"]'` or `'["matras"]'` → PostgreSQL `'[]'::jsonb` or `'["kursi"]'::jsonb` or `'["matras"]'::jsonb`
    - All other columns (name, description, duration_min, estimated_calories) stay the same

    **Foods (201+ rows from init.sql lines 181-403):**
    - 8 INSERT blocks by category: proteins (38 items), carbs (30 items), vegetables (33 items), fruits (27 items), dairy (20 items), fats (15 items), drinks (15 items), other (23 items)
    - user_id = NULL for all seeded foods
    - is_custom = FALSE for all seeded foods
    - Name, calories_per_100g, category values stay the same
    - ON CONFLICT DO NOTHING at the end of each INSERT block to handle re-runs gracefully

    Category ordering from init.sql: proteins → carbs → vegetables → fruits → dairy → fats → drinks → other
    
    Include a section comment header before each category block matching init.sql structure for clarity:
    `-- proteins (38 items)` etc.
