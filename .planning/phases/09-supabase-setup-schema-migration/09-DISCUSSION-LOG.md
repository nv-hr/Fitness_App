## PostgreSQL Schema Decisions

| Option | Description | Selected |
|--------|-------------|----------|
| PostgreSQL ENUMs | CREATE TYPE ... AS ENUM — preserves type safety | ✓ |
| TEXT + CHECK constraints | Flexible, easier to modify, less type safety | |
| GENERATED BY DEFAULT AS IDENTITY | SQL:2003 standard, allows manual inserts | ✓ |
| SERIAL pseudo-type | Legacy PostgreSQL approach, simpler syntax | |
| TIMESTAMPTZ | Stores UTC internally, timezone-aware | ✓ |
| TIMESTAMP WITHOUT TIME ZONE | Matches MySQL behavior, simpler | |
| Application-managed updated_at | Set from Node.js code on updates | ✓ |
| PostgreSQL trigger | Auto-updates via trigger function | |

**User's choice:** PostgreSQL ENUMs, GENERATED BY DEFAULT AS IDENTITY, TIMESTAMPTZ, Application-managed updated_at

## Seed Data Migration Strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Manual SQL translation | Rewrite INSERT statements as PostgreSQL-compatible seed.sql | ✓ |
| pgloader from MySQL dump | Automated but may produce imperfect PostgreSQL | |
| JSONB with proper syntax | `'["value"]'::jsonb` — PostgreSQL native | ✓ |
| TEXT columns with JSON strings | Pass through, no DB validation | |
| psql CLI | `psql $DATABASE_URL -f seed.sql` — no file size limit | ✓ |
| Supabase SQL Editor | Paste into dashboard — may hit 1MB limit | |
| Separate files | schema.sql + seed.sql — easier to re-run seed independently | ✓ |
| Single migration.sql | One file, simpler, matches current init.sql pattern | |

**User's choice:** Manual SQL translation, JSONB, psql CLI, separate schema.sql + seed.sql files
