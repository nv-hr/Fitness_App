  <files>(no files modified — runs psql commands)</files>
  <read_first>backend/db/schema.sql, backend/db/seed.sql</read_first>
  <what-built>
    Executes the PostgreSQL schema DDL and seed data INSERTs against the Supabase database.
  </what-built>
  <action>
    Apply the migration files to the Supabase PostgreSQL database using psql.

    **Prerequisites** (verified by user before this checkpoint):
    - DATABASE_URL is set in backend/.env with real Supabase credentials
    - Supabase project exists and is accessible
    - psql CLI is installed (comes with PostgreSQL, or available via `npx supabase db`)

    **Step 1: Apply schema.sql**
    ```
    psql "$(grep DATABASE_URL backend/.env | cut -d= -f2-)" -f backend/db/schema.sql
    ```

    **Step 2: Verify tables exist**
    ```
    psql "$(grep DATABASE_URL backend/.env | cut -d= -f2-)" -c "\dt"
    ```
    This should list: users, profiles, foods, food_logs, activities, user_activity_log

    **Step 3: Apply seed.sql**
    ```
    psql "$(grep DATABASE_URL backend/.env | cut -d= -f2-)" -f backend/db/seed.sql
    ```

    **Step 4: Verify data exists**
    ```
    psql "$(grep DATABASE_URL backend/.env | cut -d= -f2-)" -c "SELECT COUNT(*) FROM activities; SELECT COUNT(*) FROM foods;"
    ```
    Expected: 35 activities, 201+ foods.

    **Alternative (if psql not installed):**
    Use Supabase SQL Editor in the dashboard. Open each file (schema.sql, seed.sql) and paste into the SQL Editor, execute each in sequence. However, D-15 specifies psql as preferred to avoid the 1MB SQL Editor limit (seed.sql may be large).

    **Error handling:**
    - If `psql` command not found: Run `choco install postgresql` (Windows) or `brew install postgresql` (macOS) or use `npx supabase db` commands.
    - If connection fails: Verify DATABASE_URL is correct in backend/.env. Run `node scripts/verify-supabase-connection.js` to test.
    - If table already exists: The `IF NOT EXISTS` patterns in schema.sql prevent errors. Proceed.
    - If INSERT conflicts: The `ON CONFLICT DO NOTHING` patterns prevent duplicate errors. Proceed.

    Per D-15: Use `psql $DATABASE_URL -f` for execution (no file size limit).
    Per D-03: Manual SQL execution (not supabase db push).
  </action>

    2. Verify activity count: `psql $DATABASE_URL -c "SELECT COUNT(*) FROM activities;"` should return 35

    From the project root directory:
    ```
    node scripts/verify-supabase-connection.js
    ```

    **Expected output:**
    ```
    Supabase connected successfully
    Result: { connected: 1 }
    ```
    Exit code should be 0.

    **Troubleshooting:**
    - If `Error: Cannot find module 'pg'`: Run `npm install pg` in backend/ directory first
    - If `Error: connect ECONNREFUSED`: Supabase project may not be running. Check Supabase dashboard
    - If `Error: no pg_hba.conf entry`: Check Supabase dashboard → Authentication settings
    - If `Error: password authentication failed`: Verify DATABASE_URL password in backend/.env
    - If `Error: connect ETIMEDOUT`: Check network connectivity. Supabase uses port 6543 (not 5432). Verify the port in DATABASE_URL

    Per D-06: This is a standalone one-shot script that loads .env, connects via pg Pool, runs SELECT 1, and logs success.
    Per D-07: Uses single DATABASE_URL connection string (standard PostgreSQL approach).

    This does NOT modify server.js startup — that integration happens in Phase 10.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-09 | Information Disclosure | DATABASE_URL in psql process | mitigate | DATABASE_URL read from .env (not passed as literal); psql commands read from file, not stdin |
| T-09-10 | Denial of Service | psql connection failure | accept | If Supabase is unreachable, the apply step fails safely — no partial state is committed (DDL is transactional) |
| T-09-11 | Tampering | SQL file injection | mitigate | schema.sql and seed.sql are static files committed to git — no dynamic content; verify script uses parameterized SELECT 1 query |
| T-09-12 | Repudiation | Connection failure logging | mitigate | verify script writes "Supabase connection failed: {message}" to stdout — provides audit trail for debugging |
</threat_model>
