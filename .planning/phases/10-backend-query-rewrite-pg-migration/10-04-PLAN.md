    **Key PostgreSQL JSONB difference:**
    MySQL `JSON_OVERLAPS(goal_tags, CAST(? AS JSON))` checks if two JSON arrays overlap (share any elements).
    PostgreSQL `?|` operator on JSONB columns checks if any strings in the text array on the right exist as top-level keys in the JSONB document.

    Since `goal_tags` stores JSON arrays like `'["lose_weight","maintain"]'` (not JSON objects), the `?|` operator won't work directly — it checks for top-level keys in JSONB objects, not elements in JSONB arrays.

    **Solution:** Use the `?|` operator with a text array cast after converting the JSONB array to text array using `jsonb_array_to_text_array()` or use the `@>` containment operator:
    ```sql
    WHERE goal_tags ?| ARRAY['lose_weight', 'maintain']
    ```
    Actually, the `?|` operator on JSONB checks for key existence (top-level keys in an object), not array elements. For JSONB arrays, use:
    ```sql
    WHERE goal_tags @> $1::jsonb
    ```
    where `$1::jsonb` is a JSONB array. This checks if `goal_tags` contains all elements of the right-hand array.

    But wait — `@>` is containment, meaning it checks if the left JSONB array contains ALL elements of the right array. That's different from `JSON_OVERLAPS` which checks if ANY elements overlap.

    For overlapping arrays in PostgreSQL, the correct approach is to use the `?|` operator BUT treat the JSONB as a document where each array element is a key. No, that's wrong too.

    The cleanest PostgreSQL equivalent of MySQL `JSON_OVERLAPS` for a JSONB array is:
    ```sql
    SELECT * FROM activities 
    WHERE goal_tags ?| $1
    ```
    Where `$1` is a `text[]` array. The `?|` operator on a JSONB array checks if any of the strings in the text array exist as elements in the JSONB array.

    Actually wait — `?|` works on JSONB values (which can be arrays or objects). For JSONB arrays, it checks if any element of the text array matches any element of the JSONB array. Let me verify.

    In PostgreSQL documentation:
    - `?|` (text[]) → Do any of the strings in the text array exist as top-level keys/elements?

    For JSONB arrays like `'["lose_weight", "maintain"]'::jsonb`, the `?|` operator checks if any of the array elements match the provided strings. This IS the correct equivalent of MySQL `JSON_OVERLAPS`.

    The param should be passed as a text array (text[]), not a JSON string:
    ```javascript

    const { rows } = await pool.query(
      'SELECT * FROM activities WHERE goal_tags ?| $1 ORDER BY RANDOM() LIMIT $2',

    );
    ```

    Wait, but the existing code does `const tagsJson = JSON.stringify(goalTags)` and then passes it as a string to MySQL which uses `CAST(? AS JSON)`. For PostgreSQL, we need to pass the array directly as a `text[]` parameter. The pg driver handles array serialization automatically when you pass a JavaScript array.

    Actually, pg's parameter binding handles JavaScript arrays as PostgreSQL arrays. So `[tagsJson]` where tagsJson is `['lose_weight', 'maintain']` becomes a PostgreSQL `text[]` array parameter, which `?|` accepts.
