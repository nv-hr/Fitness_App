<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host → MySQL container | Exposed port 3306 — database accessible from host network |
| Host → Adminer container | Exposed port 8080 — web UI accessible from browser |
| Container network → MySQL | Adminer and backend services connect via fitness_net bridge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | MySQL auth | mitigate | MySQL requires DB_ROOT_PASSWORD, DB_USER+DB_PASSWORD from .env — no default credentials |
| T-09-02 | Information Disclosure | Adminer web UI on 8080 | accept | Dev-only tool on localhost; production deployment (future) would restrict with nginx auth or remove Adminer entirely |
| T-09-03 | Elevation of Privilege | Adminer root access | accept | Adminer uses MySQL user credentials from .env (DB_USER=admin), not root; root password used only for MYSQL_ROOT_PASSWORD init |
| T-09-04 | Tampering | init.sql mount | accept | init.sql is version-controlled; any change requires git commit — reasonable for dev workflow |
</threat_model>
