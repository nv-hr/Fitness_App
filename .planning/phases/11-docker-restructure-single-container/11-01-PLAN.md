    - `dist/` — Excludes any stray dist directories. The builder stage produces its own `dist/`.
    - `coverage/` — Excludes test coverage reports.
    - `Dockerfile` — Excludes itself from the build context (standard convention).
    - `.dockerignore` — Excludes itself (tiny but conventional).

    What is NOT excluded: `backend/`, `frontend/`, `package*.json` — these are needed by the Dockerfile's COPY instructions.

<task type="auto">
  <name>Task 2: Create multi-stage Dockerfile at repo root</name>
  <files>
    Dockerfile
  </files>
  <action>
    Create `Dockerfile` at repo root with three named stages per D-01 through D-06 and D-08.

    The file replaces both `backend/Dockerfile` and `frontend/Dockerfile`. Build context `.` covers both `backend/` and `frontend/` directories.

    ```dockerfile
    # syntax=docker/dockerfile:1
    FROM node:20-alpine AS builder

    # Stage 1: Build the React frontend
    # Install ALL dependencies (including devDeps like Vite) — D-04 applies only to production stage
    WORKDIR /app/frontend
    COPY frontend/package*.json ./
    RUN npm ci

    # Build the React app (output: frontend/dist/)
    COPY frontend/ ./
    RUN npm run build

    # ─────────────────────────────────────────────────

    FROM node:20-alpine AS development

    # Stage 2: Development — hot-reload backend, no frontend build
    # (Frontend runs via Vite dev server on host or separate container during dev)
    WORKDIR /app
    COPY backend/package*.json ./
    RUN npm install
    COPY backend/ ./
    ENV PORT=80
    EXPOSE 80

    CMD ["npm", "run", "dev"]

    # ─────────────────────────────────────────────────

    FROM node:20-alpine AS production

    # Stage 3: Production — serves both Express API and built React frontend

    # Install curl for HEALTHCHECK per D-08
    RUN apk add --no-cache curl

    WORKDIR /app

    # Install only production dependencies per D-04
    COPY backend/package*.json ./
    RUN npm ci --omit=dev

    # Copy backend source code
    COPY backend/ ./

    # Copy built frontend from builder stage to ./public (served by Express.static per D-02)
    COPY --from=builder /app/frontend/dist ./public

    # Default to port 80 per D-06
    ENV PORT=80
    EXPOSE 80

    # HEALTHCHECK per D-08 — curl hits /api/health on container's localhost:80
    # Agent's discretion: 30s interval, 3s timeout, 10s start period, 3 retries (standard defaults)
    HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
      CMD curl -f http://localhost:80/api/health || exit 1

    # Production CMD per D-03 — uses "npm start" (maps to "node src/server.js" per backend/package.json)
    CMD ["npm", "start"]
    ```

    **Critical implementation details:**
    - Builder stage uses `npm ci` (without `--omit=dev`) because `vite` is a devDependency in `frontend/package.json`. Using `--omit=dev` here would fail with `Error: Cannot find module 'vite'` (Research Pitfall 1).
    - Production stage uses `npm ci --omit=dev` to minimize image size and reduce CVE surface (dev tools like nodemon, jest, supertest are excluded).
    - Layer order optimized for caching: `package*.json` first (rarely changes), source code second (changes frequently), frontend build last (most volatile per research).
    - `ENV PORT=80` ensures `server.js` listens on port 80 inside the container (`server.js` defaults to PORT env or 3001) — prevents Research Pitfall 3 (port mapping confusion).
    - Production CMD uses `["npm", "start"]` rather than `["node", "src/server.js"]` per locked decision D-03. The `backend/package.json` `"start"` script runs `"node src/server.js"`.
    - The `development` stage keeps `npm install` (not `npm ci`) and includes devDeps (nodemon) for hot-reload workflow.
    - The `public/` directory is created at runtime inside the container by `COPY --from=builder`. It does NOT need to exist on the host.

    **What NOT to do:**
    - Do NOT create a `backend/public/` directory on the host — it exists only inside the container.
    - Do NOT change `backend/` or `frontend/` `package.json` files — they are used as-is.
    - Do NOT add `RUN mkdir public` — the COPY instruction creates the directory automatically.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem → Docker build context | `.dockerignore` governs what enters the build context — prevents secrets from being included in the image |
| Image layers → Runtime container | Multi-stage build excludes dev tooling (build tools, test frameworks) from the production image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | Docker build context | mitigate | `.dockerignore` excludes `.env` — secrets never enter build context (ASVS V12) |
| T-11-02 | Tampering | Production image | mitigate | `npm ci --omit=dev` excludes devDeps from production image — reduces CVE surface |
| T-11-03 | Information Disclosure | Image layers | mitigate | Multi-stage build: only runtime artifacts in final stage; builder stage layer cache contains build tools but is discarded in final image |
| T-11-04 | Denial of Service | Container runtime | mitigate | Docker HEALTHCHECK detects unhealthy state; `restart: unless-stopped` enables auto-recovery |
| T-11-05 | Elevation of Privilege | Container shell | accept | Alpine includes `/bin/sh`; switching to distroless would eliminate shell access at the cost of HEALTHCHECK complexity. Accepted per user decision (chose alpine over distroless). |
</threat_model>
