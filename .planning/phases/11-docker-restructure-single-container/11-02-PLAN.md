    **Critical implementation details:**
    - **No import changes needed** — `express.static` is part of Express core (already imported via `import express from 'express'`)
    - **No `__dirname` needed** — `express.static('public')` resolves relative to `process.cwd()`, which in the Docker container is `/app` (the WORKDIR). The Dockerfile copies frontend build to `/app/public/`. Using a relative string path is intentional — it matches the container's WORKDIR.
    - **`res.sendFile` with `root: 'public'`** — same resolution logic as express.static. The `public/` directory is relative to `cwd` which is `/app` in the container.
    - **SPA catch-all checks `/api` prefix** — If the request starts with `/api`, it calls `next()` to pass through to the 404 handler (Research Pitfall 4 prevention). This ensures unknown API routes return JSON `{"error": "Route not found"}` instead of HTML.
    - **CORS config unchanged** — per D-07, the existing CORS middleware at lines 24-29 is untouched. The default FRONTEND_URL `http://localhost:5173` remains — harmless for same-origin production requests.
    - **The middleware order is now**: security → CORS → compression → logging → body parsing → cookie → passport → rate limiters → API routes → Google OAuth → **express.static** → **SPA catch-all** → 404 handler → global error handler.

    **What NOT to do:**
    - Do NOT add `import path from 'node:path'` — the relative path string approach works with WORKDIR /app in the container
    - Do NOT remove or modify the existing 404 handler (lines 122-124) — the SPA catch-all only intercepts non-API routes; `/api/*` 404s still reach the JSON 404 handler
    - Do NOT modify CORS config (D-07)
    - Do NOT add `res.sendFile` with absolute paths — the relative `root: 'public'` approach matches the Dockerfile's WORKDIR
    - Do NOT add `app.use(express.static('public'))` before API routes — static files should not intercept API paths

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client HTTP request → Express SPA catch-all | Any HTTP request to the container port reaches the SPA catch-all if it doesn't match an `/api/*` route |
| Frontend static files → Browser | Built React app served via `express.static('public')` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06 | Spoofing | SPA catch-all | mitigate | SPA catch-all checks `req.path.startsWith('/api')` before routing — unknown API paths reach the JSON 404 handler instead of returning HTML |
| T-11-07 | Information Disclosure | express.static | accept | Static file serving exposes the React app's file listing if directory listing is enabled. Express's `express.static` defaults to `dotfiles: 'ignore'` and no directory listing — this is acceptable. If stricter isolation is needed, add Nginx in a future phase. |
| T-11-08 | Denial of Service | Static file serving | accept | Large concurrent static file requests could impact API performance. At this scale, Express.static() is adequate per out-of-scope decision (no nginx/Caddy). Mitigation deferred to Phase 12 load testing if needed. |
</threat_model>
