## Layout & Component Structure

### 1. Days Selector Panel

**Location:** WeeklyPlanPage.jsx — rendered in the empty state section, below EmptyStatePlan.

```
┌─────────────────────────────────┐
│  No Weekly Plan Yet             │
│                                 │
│  [Generate My Weekly Plan  ➤]   │  ← existing #16a34a green button
│                                 │
│  ┌─ Select training days (optional) ▼ ──┐  ← toggle header, #f3f4f6 bg
│  │                                      │
│  │  ☐ Mon   ☐ Tue   ☐ Wed   ☐ Thu     │  ← 7 checkboxes, 2 rows (4 + 3)
│  │  ☐ Fri   ☐ Sat   ☐ Sun             │
│  │                                      │
│  │  4 of 7 training days selected       │  ← validation hint below boxes
│  └──────────────────────────────────────┘
└─────────────────────────────────┘
```

**Container:** max-width 600px (matches existing page), margin auto.
**Toggle header:** 12px vertical padding (matching DayCard header), 16px horizontal padding, #f3f4f6 bg, 1px #e5e7eb border, 8px border-radius.
**Body (expanded):** 16px padding, 1px #e5e7eb border, border-top: none, border-radius: 0 0 8px 8px.
**Checkbox rows:** flex-wrap layout. 8px gap between items. Each checkbox is ~80px wide (fits 4 per row on mobile).
**Validation hint:** 8px margin-top from checkboxes, 14px font.

**Behavior:**
- Panel starts collapsed (closed) by default
- Click toggle header to expand/collapse
- Mon, Tue, Thu, Sat pre-checked by default (= 4 days)
- Unchecking below 4 or checking above 6 shows red validation hint
- Generate button is disabled when count < 4 or count > 6 (or shows a tooltip/validation)
- When Generate is clicked, pass `availableDays: {selectedCount}` in the API body

### 2. Rest Day Cards

**Location:** WeeklyPlanPage.jsx — rendered alongside regular DayCard components.

```
┌──────────────────────────────────────┐
│  Rest Day — Monday, January 5      │  ← #f0fdf4 bg, #bbf7d0 border
│                                      │
│  🛌 Take a rest. Recovery is        │  ← #666 text, 14px, line-height 1.5
│  essential for progress.            │
│                                      │
│  (no expand/collapse, no regenerate) │
└──────────────────────────────────────┘
```

**Container:** Same 1rem margin-bottom as DayCard. 12px padding header + 12px padding body.
**Background:** #f0fdf4 (light green).
**Border:** 1px #bbf7d0, 8px border-radius.
**Header:** Bold 16px "Rest Day — {formatted date}", no expand toggle.
**Body:** Single paragraph with rest message (no activity list, no buttons).
**No expand/collapse:** The card is always expanded showing the rest message. It's a static display card.
**No Regenerate Day button:** Omitted for rest days.
**No swap buttons:** N/A — rest days have no activities.

**Integration:** DayCard receives `day.rest_day` boolean. When true, render rest day layout instead of the normal expandable card layout.

### 3. Swap Button (in DayActivityRow)

**Location:** DayActivityRow.jsx — right side of each activity row, after the duration/intensity text.

```
┌───────────────────────────────────────────────┐
│  Running       30min · moderate    [Swap]     │
│  ──────────────────────────────────────────── │
│  Yoga          45min · light       [Swap]     │
│  ──────────────────────────────────────────── │
│  Cycling ⏳    60min · vigorous    [Spinner]  │
└───────────────────────────────────────────────┘
```

**Swap button:** inline-block, 56px wide × 28px tall, 14px bold, #16a34a text, #f0fdf4 bg, 1px #bbf7d0 border, 4px border-radius. Cursor: pointer. Min-height: 28px (not 44px because it's inline in a row, not a standalone tap target — but on mobile ensure sufficient padding).

**Loading state (swap-in-progress):** The Swap button on the specific row is replaced with a CSS spinner (12px × 12px, 2px border, #16a34a border, transparent top, border-radius 50%, spin animation). The row gets `opacity: 0.6` to indicate it's being modified.

**Disabled state:** Swap button `opacity: 0.5`, cursor: not-allowed when:
- A swap is already in progress on any row in the same card
- Rate-limited (retry timer active)

**Rate-limited state:** Button shows countdown like existing RateLimitedButton: "Wait 1:30" pattern but inline.

**Swap success:** The activity row data updates in place (new name, duration, intensity, calories). No toast. No animation beyond the spinner stopping and opacity returning to 1.

**Swap error:** Toast appears at top. The row returns to its pre-swap state (spinner removed, re-enable button).

### 4. Toast Notification (new component)

**Location:** Toast.jsx — rendered at the top of WeeklyPlanPage, fixed-position banner.

```
┌─────────────────────────────────┐
──┤ ✕ Could not swap activity.    │ ← #fef2f2 bg, #fecaca border, fixed top
  │    Please try again.          │    centered, max-width 400px
  └────────────────────────────────┘
```

**Container:** Fixed position, top: 16px, left: 50%, transform: translateX(-50%), z-index: 1000.
**max-width:** 400px.
**Background:** #fef2f2, border: 1px #fecaca.
**Border-radius:** 8px.
**Padding:** 12px 16px.
**Shadow:** 0 2px 8px rgba(0,0,0,0.1).
**Text:** 14px, #991b1b.
**Dismiss button:** "✕" in top-right corner of toast, 16px, cursor pointer.
**Auto-dismiss:** After 6000ms via setTimeout.
**Click dismiss:** Click anywhere on toast to dismiss immediately.
**Multiple toasts:** Only one toast visible at a time. New error replaces current.

## Interactions

### Days Selector Flow

```
1. Page loads (no plan exists)
   ↓
2. EmptyStatePlan renders with heading, description, Generate button
   ↓
3. Below Generate button: days selector panel (collapsed by default)
   ↓
4. User clicks toggle header → panel expands
   ↓
5. 7 checkboxes shown. Default: Mon, Tue, Thu, Sat checked.
   ↓
6. User clicks checkbox → toggle checked state → validation hint updates:
   - 0-3: "Select at least 4 training days" (red)
   - 4-6: "4 of 7 training days selected" (grey)
   - 7:   "Select at most 6 training days" (red)
   ↓
7. User clicks "Generate My Weekly Plan":
   - If 4-6 selected: API call with availableDays={count}
   - If <4 or >6: Generate button is disabled
   ↓
8. During generation: checkboxes disabled. Panel stays visible.
```

### Rest Day Card Display Flow

```
1. WeeklyPlanPage receives plan from API
   ↓
2. Iterate plan.days array
   ↓
3. For each day:
   - If day.rest_day === true → render DayCard in rest day mode
   - If day.rest_day === false → render DayCard in normal expandable mode
   ↓
4. Rest day cards are static (no expand/collapse, no regenerate, no swap)
   ↓
5. Rest day cards ordered chronologically with activity days (Mon-Sun)
```

### Swap Button Flow

```
1. User views expanded DayCard
   ↓
2. Each activity row shows "Swap" button on the right
   ↓
3. User clicks "Swap" on row with activity_id=5
   ↓
4. That row ONLY enters loading state:
   - opacity: 0.6
   - Button replaced by CSS spinner
   - Other rows in same card remain interactive
   - Other day cards remain interactive
   ↓
5. API call: POST /api/weekly-plans/swap-activity
   body: { activityId: 5, dayIndex: 2, weekStart }
   ↓
6. On success (200):
   - Plan state updates with new activity data
   - Activity row re-renders with new activity name, duration, intensity
   - Spinner stops, opacity returns to 1
   - No toast
   ↓
7. On error (rate limited):
   - Button shows countdown "Wait Xs"
   - Toast: "Swap limit reached. Please wait N seconds before trying again."
   ↓
8. On error (general):
   - Row returns to idle state
   - Toast: "Could not swap activity. Please try again."
   ↓
9. User can tap toast to dismiss it immediately
```

### Toast Dismissal Flow

```
1. Error toast appears at top of page
   ↓
2. Three dismissal paths:
   a. User clicks on toast → immediate dismiss
   b. 6 seconds elapsed → auto-dismiss
   c. New error occurs → replaces current toast (old dismissed automatically)
   ↓
3. On dismiss: toast is removed from DOM via state change
```

## API Integration

### New API call (add to weeklyPlanApi.js)

```js
export async function swapActivity(weekStart, activityId, dayIndex) {
  return apiPost('/api/weekly-plans/swap-activity', {
    weekStart,
    activityId,
    dayIndex,
  });
}
```

### Modified API call

```js
// Update generateWeeklyPlan to accept availableDays
export async function generateWeeklyPlan(weekStart, availableDays) {
  return apiPost('/api/weekly-plans/generate', {
    weekStart,
    ...(availableDays != null && { availableDays }),
  });
}
```

### Data shape for swap response

```json
{
  "plan": {
    "status": "active",
    "days": [
      { "date": "2026-06-01", "activities": [...] },
      ...
    ]
  }
}
```

The swap endpoint returns the full updated plan (same shape as generate/regenerate), which replaces the current plan state.
